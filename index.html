Arduino Line Following & Obstacle Avoidance Robot Dashboard

Suggested Control Flow

  1. START
  2. Initialize pins, sensors (MPU6050, Ultrasonic, Line Sensors), and motors
  3. Read ultrasonic distance
  4. IF obstacle is too close: → Stop → Avoid obstacle → Search for line
  5. ELSE: Read line sensors
    • IF center: Drive forward
    • ELSE IF left: Steer left
    • ELSE IF right: Steer right
    • ELSE: Line lost → Slow down / Search for line
  6. Repeat Loop

Final Project Requirements

  • Uses Arduino UNO and Arduino IDE (C Language).
  • Program organized into clear, manageable functions.
  • Robot moves forward, stops, and turns independently.
  • Follows a line using 3 line sensors.
  • Measures distance using the ultrasonic sensor.
  • Performs obstacle avoidance maneuver when triggered.
  • Searches for, reacquires, and resumes line tracking.
  • Group can explain all main if / else if / else decisions.

13. Debugging Checklist

Symptom Likely Check Student Action
Robot does not move STBY pin, motor pins, power supply Check wiring and run basic motor test code.
One wheel in wrong direction DIR logic / motor orientation Reverse direction in software or switch motor wiring polarity.
Robot curves when going straight Different motor speeds Tune left/right PWM values in software.
Line following is reversed Sensor polarity Check HIGH/LOW logic conditions in line detection functions.
Robot never detects obstacle TRIG/ECHO pins or wiring Run individual ultrasonic sensor test and monitor output on Serial Monitor.
Robot stops too early/late Threshold value Tune OBSTACLE_DISTANCE value in code.
Line lost after avoidance Turn/Forward timing Tune turn duration, forward time, and search speed.
Program will not upload Board / Port / Cable Verify Board type, select correct COM port, and verify USB cable connection.

22. Final Reflection Questions Guide

Use these prompt guides when preparing your team's written report:

  1. Hardest Part: Mention specific challenges (e.g., balancing PWM for straight driving, tuning ultrasonic reflection timing).
  2. Most Important Sensor: Explain why (e.g., Line sensors for primary navigation vs. Ultrasonic for safety/obstacle handling).
  3. Motor Speeds: Document your left vs. right PWM values (e.g., Left: 180, Right: 200).
  4. Obstacle Threshold: State your threshold in cm (e.g., 15 cm).
  5. Line Reacquisition Strategy: Explain your search routine (e.g., pivot turning until middle sensor reads dark).
  6. Debugging Example: Provide a concrete issue faced (e.g., false ultrasonic readings fixed by adding micro-delays).
